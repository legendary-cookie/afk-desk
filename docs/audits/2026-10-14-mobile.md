## Needs verification

- **Recursive server components:** `bot-manager.cjs:206-215,519-535,685-715` and `resource-pack.cjs:416-426` lack depth/node budgets. Direct helper input with 12,000 nested empty `extra` nodes reproduced host `RangeError`. Upstream packet/JSON limits and on-device event handling remain unverified; the old saved report's P1 remote-engine-crash interpretation is therefore narrowed to a parser robustness candidate. Add bounded iterative parsing and per-event fallbacks.
- **Microsoft token cache storage and deletion:** `main.js:5-7` selects app-private `minecraft-profiles`; `bot-manager.cjs:40-59` supplies the profile to Microsoft-authenticated Mineflayer. The installed auth library uses JSON FileCache, while `App.tsx:316-319` deletes the account record and disconnects without purging that profile. Keychain protects proxy passwords, not these token files. Inspect disposable device auth caches, permissions and post-deletion retention; do not infer cross-app readability merely from JSON storage. Backup is disabled by the Android manifest.
- **Aggregate resource-pack memory:** per-download (100 MB), parsed JSON (100 MB), texture (16 MB) and eight-entry cache caps do not establish a decoded-memory budget across live sessions. Test bounded adversarial packs on supported low-memory devices before selecting a safe aggregate limit.
- **Bridge input contract:** `main.js:14` destructures commands before its try block; `App.tsx:55-67,106-119` maintains reply/event promises without full runtime schemas. The bridge is local RN-to-Node, not an exposed remote control port. Malformed local bridge messages/process restart recovery need targeted tests; a remote attacker path was not established.

## Claims and native review

Reviewed account persistence/migration, external links, foreground session synchronization, RN lifecycle/retry/persistence paths, the embedded command bridge and bot/resource/proxy/profile/version modules, Android activity/application/service registration, manifest/signing/Proguard settings and iOS project/Info.plist configuration. Compatibility patches were reapplied during isolated installs. This is focused source review with mocked host tests, not mobile dynamic penetration testing or exhaustive coverage of every screen.

Current storage code verifies newly written Keychain credentials before replacing plaintext snapshots (`account-storage.ts:50-89`), serializes snapshots, and retires referenced secrets after the snapshot commit. Old unreferenced secure revisions may survive ambiguous failures as the hardening note states. Names, hosts, proxy routing/username and other account configuration remain in AsyncStorage; proxy passwords are removed from persisted snapshots. Native Keychain hardware guarantees are not proven by mocks.

The Android helper serializes session counts, stops at zero and makes notification requests asynchronous. Native `AfkForegroundService.kt` returns `START_NOT_STICKY` and stops empty restarts; `AfkForegroundServiceModule.kt` validates counts, starts/updates/stops the service and reports native exceptions. The manifest disables backup and exports only the launcher activity, not the service. Signing checks require original release credentials and contain no debug fallback (`android/app/build.gradle:101-133`). These source contracts match `docs/HARDENING-STATUS.md`; OS background restrictions, denied notifications, process death, signed APK upgrade and actual native start/stop were not tested.

The iOS plist disallows arbitrary transport loads, allows local networking, and has no general background guarantee. Its project still declares marketing version 0.1.0; mobile and embedded package versions are 0.9.2. See the hygiene audit for documentation/version consequences.

Fresh host results: Jest 32/32 across five suites; embedded engine 28/28; TypeScript and quiet ESLint exit 0. Host Node is 26.8.1. No Android/iOS package was built or installed. The top-level RN dependency graph has current advisories; passing unit/type checks is not release readiness.
