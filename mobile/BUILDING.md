# Building AFK Desk Mobile

These instructions build Android **0.9.2**.

## Android

The release configuration supports ARM64 and 32-bit ARM devices running Android 7.0 or newer.

Install JDK 17, Android SDK Platform 35, Build Tools 35.0.0, NDK 26.1.10909125, and CMake 3.22.1. Then run:

```powershell
npm ci
cd nodejs-assets/nodejs-project
npm ci
npm prune --omit=dev --ignore-scripts
cd ../../android
./gradlew assembleRelease
```

On Windows, use a short checkout path because the embedded Node C++ build can exceed the traditional path-length limit. Release builds now require these environment variables; there is no debug-key fallback:

- `AFKDESK_ANDROID_KEYSTORE`: absolute path to the original keystore.
- `AFKDESK_ANDROID_STORE_PASSWORD`: keystore password.
- `AFKDESK_ANDROID_KEY_ALIAS`: original key alias.
- `AFKDESK_ANDROID_KEY_PASSWORD`: key password.

Set secrets outside the repository (for example through your build runner's secret configuration). Do not put them in command transcripts, source, or committed Gradle properties. Keep an offline backup of the original key. No production key is supplied or regenerated by this repository.

### Updating without losing data

Keep `applicationId` as `com.afkdeskmobile`, retain the original signing identity, and increase `versionCode` for a distributed update. Android checks signing identity for updates; see [Android app signing](https://developer.android.com/studio/publish/app-signing). If an existing beta was debug-signed, its exact original debug key is required for an in-place update; a newly generated key is not equivalent.

Use an in-place package update, not uninstall/reinstall. If Android reports a signature mismatch, stop and recover the original signing key. Never uninstall or clear app storage to bypass that error. The account storage key remains `afkdesk.mobile.accounts.v1`; secure proxy-password migration preserves the old snapshot until encrypted storage is verified and the new snapshot commits.

Before distributing, test an old-version install containing disposable accounts, update it with the new signed APK, then confirm accounts, proxy authentication, and reconnect settings survive. A debug build was launched on an Android 14 emulator (2026-10-27) and the embedded engine reached Microsoft device-code sign-in; upgrade over 0.9.2 and ARM hardware remain unverified.

### Windows build troubleshooting

- Use a short `TMP`/`TEMP` (for example `C:\afktmp`) or Gradle fails with `"Unable to establish loopback connection"`.
- Pass JVM options via `GRADLE_OPTS` / `-Dorg.gradle.jvmargs`, never `JAVA_TOOL_OPTIONS` (its `"Picked up JAVA_TOOL_OPTIONS"` stderr line makes prefab fail with `CXX1210` `"No compatible library found"`).
- npm 11 blocks `nodejs-mobile-react-native`'s postinstall — run `npm install-scripts approve nodejs-mobile-react-native` then `npm rebuild nodejs-mobile-react-native`.
- Debug builds load JS from Metro unless you run `node node_modules/react-native/cli.js bundle --platform android --dev false --entry-file index.js --bundle-output android/app/src/main/assets/index.android.bundle --assets-dest android/app/src/main/res`.
- The default ABIs are ARM only, so `x86_64` emulators need `-PreactNativeArchitectures=arm64-v8a,armeabi-v7a,x86_64` and adding `x86_64` to `abiFilters` in a local build.
- A debug build needs `android/app/debug.keystore` (generate with `keytool`, standard `androiddebugkey`/`android` values) — never commit it.

## iPhone and iPad

Apple builds require macOS, Xcode, CocoaPods, and an Apple development team:

```bash
npm ci
cd nodejs-assets/nodejs-project
npm ci
npm prune --omit=dev --ignore-scripts
cd ../..
cd ios && pod install
```

Open `ios/AFKDeskMobile.xcworkspace`, select your development team, and run on your device. Apple requires signing even for personal installations. iOS may suspend Minecraft sockets after the app is backgrounded, so reliable continuous background operation is Android-only.

Install engine development dependencies before pruning: `patch-package` is needed
by the install hook to apply the compatibility patches. These instructions have
not been verified on macOS during the September light audit.
